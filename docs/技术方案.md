## 1. 项目定位（两层结构）

| 层 | 内容 | 性质 |
|---|---|---|
| **基础盘** | 计算机学科（数据结构与算法等）**实训教学软件**——"学（RAG 知识库）—练（CodeLab 判题）—测（学情诊断）—复习（错题本）"完整学习闭环 | 产品成立的前提，评委判断"这是一个基本的软件"的底线 |
| **亮点层** | **教学时机对齐**：动态三层护栏 + 苏格拉底式分层引导（先引导、后给解），并用 DPO 把该行为内化进模型权重 | 锦上添花的差异化，让评委"眼前一亮"，但不替代基础盘 |

**一句话定位**：面向计算机学科（数据结构与算法等）实训的教学软件——学习闭环做扎实的底座，"教学时机对齐"（三层护栏 + 分层教学策略 + DPO 数据管道）做亮点，用评测闭环证明"先引导、后给解；该问时问、该讲时讲"。

**范围红线**：本项目**只做学生端**，无教师端/班级管理/教学后台——PPT 与答辩一律不提。

## 2. 系统架构

**技术栈**：前端 Vue3 + Vite + Element Plus + ECharts + CodeMirror 6；后端 Python FastAPI + PostgreSQL（无 DATABASE_URL 时回退 SQLite）；AI DeepSeek API（可切换本地模型）；RAG：ChromaDB + SiliconFlow embedding（bge-large-zh-v1.5，1024 维）；容器化 Docker Compose。

**部署拓扑**（`docker-compose.yml`，一键 `docker compose up -d --build`）：

| 服务 | 端口 | 说明 |
|---|---|---|
| student-frontend | 80 | Vue 构建产物（nginx） |
| student-backend | 8001→8000 | FastAPI，最重服务（限 1.5G，5GB 资源红线） |

- 全离线部署：缺 API key 时自动回退内置本地 LLM/嵌入，不依赖云端（合规卖点）。
- 资源红线：容器级 mem_limit 合计受控（测试报告 §5.3），Key 只走环境变量、不入库。
- 图：`docs/assets/docker_compose_architecture.drawio` / `.png`。

**代码分区**：`frontend/`（16 视图 + 8 个主导航入口，无空壳页）；`backend/`（FastAPI：`services/` 为核心业务，`routers/` 为 API）；`docs/dpo_alignment_plan.md`（DPO 管道设计）。

## 4. 亮点层：教学时机对齐（核心差异化）

### 4.1 三层护栏（输出侧时机约束）

| 层 | 机制 | 状态 |
|---|---|---|
| 规则层 | R1–R4：请求类型分类 + 苏格拉底风格边界（`answer_guard_service.py`） | ✅ 运行时生效 |
| 运行时层 | 参考解重叠度检测，超阈拦截；**流式过滤**（逐块判定，非全量后处理） | ✅ 生效 |
| 权重层 | DPO 把"先引导、后给解"内化进模型参数（NeurIPS'23 方法） | ☁️ 云端产物已回传（2026-10-14），待按修正后数据再训一轮 |

### 4.2 时机释放阀（差异化亮点）

R1 命中但满足**任一条件**即放行"参考实现 + 对照讲解"（`answer_guard_service.py` → `evaluate_release`，36 单测全过）：

1. 学生本轮贴出自己的代码 ≥3 行（已尝试）；
2. 同用户同关卡累计被拦 ≥2 轮（该给了）；
3. 该关掌握度估计 ≥0.7（`RELEASE_MIN_MASTERY`，双证据源取高、无证据不释放）。

未释放时：替换为承诺式引导话术（"把你写的版本发给我——我看到你的尝试后，对照着讲给你看"），而非拒答。对应文献：PNAS 2025 Bastani（伤害学习的是"过早直给"而非"给答案"）。

### 4.3 苏格拉底式分层教学

- **六步教学编排**（PDCA 闭环）：动作分类 `classify_move`（6 教学动作）→ 边界决策表 → 提示阶梯 `mastery_hint_level`（首轮 ≤3 行 → 中间轮指行号给概念 → 终轮给根因，单轮 ≤5 行）→ 渲染 → sandbox 复核 → 回写画像（`teaching_policy_service.py`）。
- **SayCan 式高低分离**：高层编排教学动作，低层渲染话术；`persona` 总控 + prompt 渐进降级 + ReAct 证据链路由。
- **掌握度驱动**：诊断画像 + 关卡阶段状态双证据源，掌握度越高提示越直接（示例渐退 worked-example fading）。
- **引导式再生成**：无参考解的关卡，拦截后走 2 轮引导式重生成，用裁判校验后放行。

## 5. 个性化学习路径生成（第二亮点）

**一句话**：把"让 LLM 自由写一份学习计划"升级为"**依赖图约束 + 学情画像驱动**的学习路径生成"——确定性依赖骨架保证先修顺序正确，LLM 只在骨架上做个性化编排，路径随学情**增量演化**。

### 5.1 现状与缺口（创新点从哪来）

现有实现（`learning_service.py → generate_learning_path`）是双模式：

| 模式 | 触发 | 性质 | 局限 |
|---|---|---|---|
| 模块/阶段模式 | `modules` 非空 | 确定性：`agent_course.build_course_path` 按固定阶段顺序构建；或按知识分类拼装（每类 ≤12 任务） | 顺序正确但**无个性化**，与画像/诊断解耦 |
| LLM 模式 | 无 `modules` | LLM 自由生成 JSON，后处理仅重排 `day` 编号 | 前置依赖链只是提示词里的一段文本，**顺序不保证合法**；生成一次即固定，**不随学情演化** |

三个缺口：① 顺序不保证符合先修依赖；② 粒度是"天"而非"知识点/学习单元"，无法对齐掌握度主口径；③ 一锤定音，掌握度与错题变化不回写路径。

### 5.2 生成什么（输出形态）

一条**有序、可解释、可演化**的学习路径：单位 = 学习单元（知识点 + 关联资源 + 验收口径），每个单元带"来源依据"（诊断/掌握度/错题）与"依赖位置"，整体可解释"为什么是这个顺序"。

### 5.3 输入（四源）

| 输入 | 来源 | 作用 |
|---|---|---|
| 学习目标 `goal` | 用户输入 | 锚定终点与知识覆盖范围 |
| 诊断结果 | `diagnostic_session_id` → `_get_diagnostic_result` | 锚定起点（已有基础可跳过） |
| 掌握度主口径 | `knowledge_mastery`（`basic×0.30 + explanation×0.30 + transfer×0.40`） | 决定单元取舍，档位阈值 `MASTERY_HIGH=0.7` / `MASTERY_LOW=0.4` |
| 错题本 | `error_book` | 追加补强单元 |

### 5.4 结构约束：知识点前置依赖图

- 建 **dsa 口径**的 `知识点 → prerequisites` 依赖表，与课纲、教程种子（`dsa_tutorial_seed.json`）、旗舰关 `knowledge_tag` 对齐；`agent_course.py` 的阶段固定顺序可作为骨架的上层。
- 生成前对依赖图做**拓扑排序**，得到"先修合法区间"；LLM 只能在不违反拓扑序的区间内做编排与取舍。
- **第二版（已落地，见 §5.8）**：依赖表不再只靠人工维护——`knowledge_graph_service.generate_knowledge_graph` 让 LLM 先为每个知识点生成结构化描述，再在描述基础上补全"专家表未覆盖"的先修边与全部**相似（similar）**边，落库为知识图谱（`knowledge_graphs` 表）；专家边权威、LLM 只补缺，成环的 LLM 先修边由确定性校验直接丢弃。

### 5.5 生成机制：确定性骨架 + LLM 个性化编排（三层）

与项目"稳定层 + 个性化层"哲学一致：

1. **骨架（确定性）**：依赖图 → 拓扑序 → 按目标覆盖 + 掌握度分档决定必学/可跳过集合（≥0.7 可快进、≤0.4 必补）。
2. **编排（LLM）**：只在骨架给定的合法区间内，把单元组织成阶段、配比资源类型、写验收口径与个性化说明。
3. **校验（确定性）**：校验拓扑合法性 + 目标覆盖度，不合法则约束重排/重生成（同 §4 运行时护栏"先判后放"的思路）。

### 5.6 演化：增量重排而非重生成

学情变化（掌握度更新、错题新增、关卡状态）触发**增量重排**：冻结已完成部分，只调整未完成部分——保证路径稳定、可解释、可对照。

### 5.7 创新点表述与文献边界

- **表述**：从"LLM 自由生成"升级为"**依赖图约束解码 + 学情驱动的学习路径生成与演化**"——确定性骨架兜底正确性，LLM 负责个性化，二者可分离验证（骨架可单测、编排可评测）。
- **文献挂靠**：KnowLP（AAAI 2026，arXiv 2506.22303）作为"学习路径生成"的**方法先例**，不作教育效果证据。
- **如实边界**：我方为"依赖表 + 拓扑约束 + LLM 编排"，**非**认知诊断（同 [ppt_structure.md](ppt_structure.md) 措辞红线）；第二版的知识图构建借鉴 KnowLP 的 EDU-GraphRAG「自适应构建知识结构图」**思路**，但落地为"LLM 依据知识点名与描述推断关系"，**不是** GraphRAG 的检索建图，**不做**强化学习路径生成（KnowLP 的 DLRL）训练。
- **知识来源（答辩常问）**：只吃"**知识点名单**"（来自路线图站点的 `knowledge_tag`），**不依赖教材 PDF、不需要外部语料**；专家先修表（`data/dsa_prerequisites.json`，人工维护）作为权威约束注入，LLM 只补缺。

### 5.8 展示形态（2026-10-16 定）

> **两版关系**：**第一版已落地**（路线图 + 进度表）；**第二版亦已落地**（知识图谱·网状，同为页面内视图）。

**主视图 = 路线图·学习地图**（第一版）。三个创新要素在**一张图**上同时显性化：

- **个性化** → 节点按掌握度分档着色：≥0.7 可快进 · 0.4–0.7 在学 · ≤0.4 需补强；当前站高亮为**唯一焦点**（品牌色描边 + 填充）。
- **依赖约束** → 连线 = 先修依赖，**箭头方向即拓扑序方向**（分层布局的层级 = 拓扑深度）。
- **演化** → 增量重排后，在受影响节点打**变更标记**（对应 §5.6）。

**进度表**：每个阶段/单元带完成度，整条路径显示"已完成 N / 共 M 站 + 当前位置"；现有 Dashboard「今日学习任务」卡升级为"**路线第 N 站**"。这一步先做，保证第一版即可用。

**交互**：节点可点 → 跳对应资源（教程 / 旗舰关 / 练习 / 错题），闭环回 §3；13 关只作为**节点可点的落地资源**，不做前置门控。

**第二版 = 知识图谱·网状（已落地）**：`LearningPath.vue` 顶部提供「学习路线图 / 知识图谱」视图切换，知识图谱是**独立的网状视图**（此前规划的"单站详情二级视图"落地时改为同页视图切换，节点点击仍有二级详情抽屉）。网状图只表达"关联密度"，**不承担顺序与进度**，故切到该视图时隐藏阶段进度表。

- **节点** = 知识点，颜色沿用掌握度分档，**大小随关联度**（degree）增大；点击弹出抽屉，展示 LLM 生成的**定义 / 关键要点**，以及**先修（入边）/ 后继（出边）/ 相似**三组关联（每条带理由与"专家 / AI"来源标记，可点击跳转）。
- **边分两类**：**先修**（灰色实线 + 箭头，方向即先后）与**相似**（紫色虚线，无方向，表示易混淆、适合对比学）。
- **生成**：未生成时页面降级展示"专家先修骨架"，点击「用 AI 构建知识图谱」调用 `POST /learning/path/graph/generate` 生成并落库（`knowledge_graphs` 表，`UNIQUE(user_id, curriculum_version)`，可重复生成覆盖）。

**数据来源**：`GET /learning/path/graph` 读库；未生成时由 `knowledge_graph_service.build_skeleton_graph` 用专家先修表拼出骨架（`has_graph=false`）。节点掌握度从路线图站点回填，保证与第一版同一套分档配色。

业界亦为此分工（成都理工大学、国家开放大学用图谱做**推荐计算**，再用路径/地图呈现结果；YT-Pilot arXiv 2604.03543 的 interactive roadmap 为同类先例）。

**技术**：复用已在用的 ECharts（`graph` 类型：第一版分层布局 `layout:'none'`，第二版力导向 `layout:'force'`），不引入新图表库。

**现状**：前端此前**无路径展示面**（`/learning-path` 曾重定向到 `/learning-docs`）；本页为新增，现含两个视图。

**状态**：✅ 第一版（路线图 + 进度表 + dsa 依赖表）与第二版（知识图谱·网状 + LLM 建图 + 相似关系）均已落地；**待做**：LLM 在合法区间内个性化编排、学情变化触发增量重排。

## 6. 评测闭环与 DPO 数据管道

**方法学**（答辩常问"怎么证明有效"）：held-out **按问题族 70/30 分组隔离**防训练/评测泄露；**四臂对照**（raw 零护栏 / 基线 / 规则护栏 / 护栏+重生成；summary 增 `guardrail_lift` 量化护栏增益）；双口径（规则字符串匹配下界 + LLM 裁判）；已跑通的评测报告在 `backend/data/eval/*.json`。

> **口径边界（2026-10-14 修正）**：held-out 四臂均带同一 system prompt 底线规则 → 工具级护栏的边际增益趋近 0（`guardrail_lift` 用于如实说明这一点）；苏格拉底基准实验（"直给 24/30→16/30"，n=30）与 CodeLab held-out 实验（"恰当给码率 0.5834"，n=12/轮）**分属两个实验，数字不可交叉解读**。

**核心数字（PPT 引用以 [ppt_structure.md](ppt_structure.md) 数字清单为准，此处为速查）**：

| 指标 | 数值 | 出处 |
|---|---|---|
| 首轮直给码率（规则口径） | 24/30（80%）→ 16/30（53.3%），相对降 33% | `direct_code_rate_report.json` |
| 首轮直给码率（裁判口径） | 28/30（93.3%）→ 24/30（80%） | `llm_judge_report.json` |
| 护栏触发 / 长代码 | 12/30；3 → 0 | 同上 |
| CodeLab 恰当给码率 | 0.5834（规则口径下界） | `codelab_heldout_report.json` |
| DPO 文本训练对 / 隔离评测对 | 871（26/19/337/97/392）/ 230 | `dpo_build_report.json` |
| DPO 工具决策对 v2（train / eval） | 1044 / 307（L4 新增 `answer_vs_modify` 26/13；`dropped_chosen_violation` 26→0 / 14→1） | `dpo_tool_convert_report.json` |
| 四层质检 | 泄漏 0.000、违规 0.000、讲解率 1.0 | `dpo_quality_audit.json` |

**DPO 如实口径（P12 用）**：首轮 DPO 已训完但判定奖励黑客（460:19 数据不对称为主因），修数据后以 IPO（AISTATS 2024，TRL 一行切换）重跑；云端产物已 2026-10-14 回传本地并回填报告，但基于 v2 修订前数据训练，**需按修正后数据再训一轮**，held-out 分层行为对照验证——**说"进行中"，不说"已训完即成功"**。
