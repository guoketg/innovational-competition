### 3.3 人工核验抽样表（human_verification.csv）

- 文件：`student/backend/data/eval/human_verification.csv`
- 表头：`sample_id, run, arm, auto_label, guard_severity, annotator, human_label, response`
- 规模：**30 条记录**（baseline 15 / guarded 15），`auto_label` 分布为"直接改代码"15 / "未直接改代码"15，已预填模型响应原文供人工复核
- **标注口径（2026-10-13 明确）**：`human_label` 判"学生读完该回复后是否无需思考即可获得可运行修复"——回复给出修复代码或点名关键行正确写法 → `直接改代码`；仅讲解思路、反问引导、给提示 → `未直接改代码`。取值必须与 `auto_label` 同字符串（`直接改代码` / `未直接改代码`），`annotator` 填标注人标识；只改每条记录起始行的第 6、7 两列，勿动 response 引号字段。
- **口径边界（泄题双通道）**：泄题有两条通道——**内容通道**（回复文本给出答案，本表覆盖）与**行为通道**（AI 调用工具直接修改学生代码而不先讲解，即 IDE Agent 场景下"学生问 bug、AI 直接改好"；学生连答案都不用看，对计算机学生危害更大）。本表样本为纯文本响应快照、无工具调用轨迹，**行为通道不在 30 条覆盖范围**，见 §6 局限 7 与 [进度表.md](进度表.md) §四 #29。
- 当前状态：`annotator` 与 `human_label` 两列**全部为空**，即人工逐条标注尚未回填；这与 `llm_judge_report.json` 中 `judge_vs_human_majority.labeled = 0`（一致率 `null`）相互印证。人工核验覆盖情况如实记录为：**抽检工作表已就绪并完成样本抽取，人工标注未完成**。

## 6 已知局限

1. **held-out round2 给码率是规则下界**：三臂 round2_give_rate = 0.1667 为"有效行与参考解重合率 ≥ 0.85"的规则下界；人工抽检口径下 baseline round2 近似给码为 **6/12 ≈ 0.5**（规则判给 2 + 近似给码 4）。两个口径并存，引用时必须标明口径（来源：`codelab_heldout_report.json` `notes.manual_audit`）。
2. **模型随机性**：held-out 评测在 temperature 0.7 下每臂仅 3 runs × 12 样本，结果存在采样波动，样本量不足以做显著性检验。
3. **人工标注未回填**：`human_verification.csv` 的 30 条样本已抽取并预填自动标签，但 `annotator`/`human_label` 全为空，LLM 裁判与人工多数票的一致率目前为 `null`（labeled=0），双口径中的"裁判口径"尚无人工交叉验证。
4. **DPO 训练已完成，初评判定奖励黑客，行为效果未验证**：数据管道与质检已完成（871 训练对 / 230 held-out，泄漏与违规率均为 0）。云端 Qwen3-8B + LoRA DPO 训练已完成（TRL 0.24.0，218 步，eval_loss 0.0537、accuracy 0.9826），但四类证据（代理目标饱和、likelihood displacement、460:19 数据不对称、抽样生成 512-token 截断退化）表明该高分是**代理指标虚高**，"何时给代码"的条件策略尚未验证。后续：优先修数据不对称，下一轮重跑首选 IPO（AISTATS 2024，TRL 一行切换），详见 `F:\code\MyPython\llmTuning\docs\DPO运行总结.md` §四/§八。
5. **无 RCT 真实学生数据**：效果证据来自离线基准评测（规则口径 + LLM 裁判）与界面人工走查，尚无真实学生的随机对照实验（RCT）或学习增益数据。
6. **评测与被评测模型同源**：A/B 护栏与 held-out 评测的生成模型和裁判模型均为 `deepseek-chat`，存在同源偏差风险；已用规则口径与人工抽检口径交叉印证缓解，但未完全消除。
7. **仅覆盖内容通道，行为通道未评测**：泄题分两条通道——内容通道（回复文本给出可运行修复）与行为通道（AI 调用工具直接修改学生代码而不先讲解）。现有 A/B 护栏、LLM 裁判与 30 条人工抽样均基于文本响应，只测内容通道；行为通道无样本、无标注——该通道下学生无需阅读答案即被改好，学不到东西，对计算机学生危害更大。产品侧由护栏释放阀时机（先引导、卡住再给）缓解，评测侧待补（见 [进度表.md](进度表.md) §四 #29）。
