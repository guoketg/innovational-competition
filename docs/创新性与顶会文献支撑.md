## 一、创新点（只列研究性贡献；工程实现另见附录）

> **2026-10-18 定稿口径**：创新点只保留 **3 条研究性贡献**——C1 **Jev 轻量意图识别**、C2 **知识图谱个性化学习路径**、C3 **DPO 对齐**。其余（请求轴代改护栏、内容护栏、掌握度脚手架、教学动作分层、评测方法学）是**工程实现与方法学**：能证明系统可用、能给出数字，但**不作为创新点**。其中"单纯防止给答案"（内容护栏）更只是**工程优化**，且已下线。

### C1 Jev：教学场景的轻量意图识别（三原语契约）
- **要解决什么**：教学助手必须先答出"这名学生这次是**要学**、还是**只要一段能跑的代码**"，才能决定该不该代改、该不该给答案。而真实输入几乎都是**图片 + 口语**，意图可伪装、可混合、可随轮次翻转。
- **做法**：**Jev 三原语契约（Choice / Score / Noul）**——用三个最小原语把"意图判定"拆成可组合、可替换的接口（当前规则版实现 = `services/request_classifier.py` 的 `judge_intent`）。置信度不足时**回落默认学习模式并触发显式选择**；**判代价不判真伪**——不识别用户真伪，只用行为信号 + 显式选择控制放行成本。
- **落地**：`decide_channel` 三档判定（学生明确要求代改 → 提示 1 次后放行；未提请求 → 不得主动代改；工具性使用 → 逃生门放行并留痕），即"请求轴代改护栏"——**这部分是工程实现，见附录附1，不计入创新点**。
- 数字（`backend/data/eval/behavior_channel_report.json`，n=25，规则口径镜像下界）：意图判定准确率 **0.92**、kind 准确率 **1.0**；恰当代改率 1.0 / 未请求主动代改率 0.0 / 过度拦截率 0.0 / 路由错误率 0.0。
- 诚实边界：Jev 现为**规则版实现**、阈值 0.55 待用真实样本校准；口径为自洽镜像，**不度量真实模型行为**。

### C2 知识图谱驱动的个性化学习路径
- **课程级知识图谱**（2026-10-17 落地）：44 个 DSA 知识点 / 123 条关系（先修 78 · 相似 14 · 包含 31）。LLM **两步建图**——先为每个知识点生成结构化描述（定义 / 关键要点 / 易混对象 / 常见迷思），再在描述基础上推断"**先修 + 相似**"双关系并给出**置信度与判断依据**（对标 EDU-GraphRAG；方法先例 KnowLP，AAAI 2026）。
- **三重可信**：专家先修表权威（`data/dsa_prerequisites.json`）、AI 只补缺；AI 边按置信度分 accepted / pending / rejected，**只有高置信且不成环的边才参与编排**；确定性校验（未知节点 / 自环 / 重复 / 成环）直接丢弃并留痕。人工可逐条采纳/拒绝（含环检测），每次生成 / 审核 / 回滚写**版本快照可回滚**，图谱按课程参数化（当前 `dsa → dsa-kg-llm-v3`）。
- **路径编排**：`plan_course_path` / `plan_knowledge_path` 四策略候选 + 五指标多目标评分 + 备选方案；先修就绪度沿边向下传播（前置未打牢则锁后继，掌握度带时间衰减，"最弱项 65% + 加权均值 35%"），未诊断知识点按中性处理不判死。44/44 知识点全部进入路线。
- **反事实解释**：`build_path_counterfactual` 对每个被卡住的目标回答"先补哪个最划算"，给出解锁知识点数、解锁内容总时长与折合周学时（不是只说"补这条边"）。
- **四维质量测评**（满分 100）：结构健康 25 / 边质量 25 / 路径影响 30 / 证据覆盖 20。2026-10-17 demo 账号实测 **总分 86.5「优秀」**（结构 100 · 边质量 80.3 · 路径影响 86.4 · 证据覆盖 77.5）；AI 提出 22 条先修边，21 采纳 / 1 待审；独立金标准已判定的 7 条 AI 边全为正例（judged 精确率 **100%**），novel 召回 44%，图谱覆盖金标准**核心正例 97.5%**。
- 诚实边界：金标准现为**单人初标**（85 条边，第二位教师未标注，kappa 待补）；多次生成稳定性未抽检；路径影响用固定掌握度的**模拟画像**（薄弱 / 中等 / 熟练），非真人前后测；三类学生先修违规率均 0%，但与基线相比顺序变化 **0 处**（硬先修与课程原顺序重合，尚未产生差异化重排）。

### C3 DPO：教学行为的离线偏好对齐
- **设计动机（与护栏的关系）**：运行时护栏解决不了根本问题——只要用户明确发起，系统就无权拦截；所以把"该不该代改、该不该给答案"的**控制逻辑下沉到权重层**，让模型自己学会"先引导、后给解；该问时问、该讲时讲"。
- 六层混合 871 训练 + 230 held-out（P 引导 / C 概念 / A 改错 / X 越狱 / G 风格）；按问题族 70/30 分组隔离
- 护栏指标复用为数据质检器（泄漏 0.000、违规 0.000、讲解率 1.0）——"指标体系与数据管线互证"
- chosen 含"无错完整讲解"413 条：**数据层已实现"时机成熟给完整讲解"**，不是学成全拒
- 状态：训练已跑（Qwen3-8B + LoRA，218 步），但四类证据判定**奖励黑客**；改进线为**修数据 + IPO（AISTATS 2024）重跑**

## 一之附录：系统实现与方法学（**不计入创新点**，仅证明系统可用、数字可复核）

### 附1 请求轴代改护栏（Jev 的工程落地）
- `decide_channel` 三档判定 + 放行留痕审计（判定内核见 C1）；`evaluate_release` 三条件降级为"免提示加速通道"
- 数字（`behavior_channel_report.json`，n=25，规则口径镜像下界）：恰当代改率 1.0 / 未请求主动代改率 0.0 / 过度拦截率 0.0 / 路由错误率 0.0；用例分布 学习 20 / 工具性使用 3 / 伪装 2

### 附2 内容护栏（"单纯防止给答案"）——工程优化，**已下线**
- 输出与参考解**文字重合**即拦截（规则 R1 + 苏格拉底风格 R2 + 流式逐块判定 + 有界重生成再检）。曾跑出对照数字：苏格拉底基准（n=60）直给码率 **78.3% → 46.7%**、长代码 **6 → 1**；LLM 裁判口径 93.3% → 80%
- **为什么下线**：它本质是"防止给答案"的**工程优化，不是创新**；且与 DPO 训练原则冲突——DPO 的 chosen 里本就含"用户要答案 → AI 给答案"的正样本（5562 条里 **48 条**会被它误判为违规，对照 hint_only 仅 2 条）。代码与历史数据保留，可回滚 / 离线复用，运行时不再调用（详见 `CLAUDE.md`）

### 附3 掌握度脚手架自适应（hint 阶梯）
- 启发式 mastery → hint_level 1–4 递进（学习科学口径 = worked-example fading 示例渐退）；阶梯日志可分析"是否过早给太多"

### 附4 教学动作分层决策
- `teaching_policy_service`：6 动作（自测 / 递进提示 / 概念联结 / 诊断 / 评价应答 / 引导下一步）+ 规则引擎（置信 0.92/0.78/0.5）→ 低置信 LLM 快分（max_tokens≈16）→ 规则兜底；决策全落库可审计，`diagnosis_focus()` 形成诊断→提示闭环

### 附5 评测方法学
- 按问题族 70/30 分组隔离 held-out（13 关：9 训练 / 4 隔离）；四臂对照（raw / baseline / guarded / guarded_regen）；双口径互证（规则下界 vs LLM 裁判口径）；**双指标防两端刷分**（首轮不给码率防过早给 + 次轮给码率防过度拒）+ 第三指标"恰当给码率"；行为通道评测（恰当代改率，双侧）；LLM-as-a-judge + 20% 人工抽检

### 3.4 纯方法出处（非教育证据，仅标注实现来源）

- DPO：Rafailov et al., **NeurIPS 2023**；Shielding：Alshiekh et al., **AAAI 2018**；LLM-as-a-judge 评测谱系——这些只说明"用了什么算法"，**不进教育论证**。
- **对齐方法改进线（回应"方法太老"，2026-10-13 调研）**：
  - **IPO**：**AISTATS 2024**（pp. 4447–4455）——抗 over-training，对症本次 DPO 奖励黑客的代理饱和与 likelihood displacement；TRL 0.24.0 `loss_type="ipo"` 一行可切（**首选**）
  - **SimPO**：**NeurIPS 2024**——长度归一化奖励，对症生成退化；0.24.0 须换 CPOTrainer（次选）
  - **ORPO**：**EMNLP 2024 Outstanding Paper**——SFT+对齐合一，改动面大（备案）
  - 话术：DPO 为基线，IPO/SimPO 为近期 venue 改进线；**2026 新方法（GAW-PO 等）全无 venue，不采用**
- **个性化学习路径方法出处（2026-10-16 核实）**：**KnowLP**——Cheng et al., *GraphRAG-Induced Dual Knowledge Structure Graphs for Personalized Learning Path Recommendation*, **AAAI 2026**（[arXiv 2506.22303](https://arxiv.org/pdf/2506.22303v2)，浙大 Kg4ex/CIKM 2023 同组）。venue 是算法会议、内容是教育应用——**只作方法先例，不作教育效果证据**；我方落地为"依赖表+掌握度规则排序"（第二版已补：LLM 依据知识点名与描述自动补全先修/相似双关系，见 §五 #9），借鉴其 EDU-GraphRAG **思路**但仍非 GraphRAG 检索建图、非认知诊断。同批另三篇（来自 `docs/nolvety.md`）：Temp-R1（ACL 2026，时序 KGQA）域不对口不采用；TKG-Thinker、KG 隐式奖励模型（均无 venue 的 arXiv）不收录

## 四、理念修正：从"拒绝给答案"到"时机受控释放"（2026-10-12）

> **2026-10-18 更新**：本节描述的"运行时护栏时机释放"已随**内容通道护栏整体下线**（下线理由见 §一 附录附2 与 `CLAUDE.md` 决策记录）。`evaluate_release` 三条件现只作为**行为通道的"免提示加速通道"**存在，不再用于放行"参考实现 + 对照讲解"。以下内容保留为**理念与历史**记录——"先引导、后给解；该问时问、该讲时讲"的产品目标仍然成立。

**修正内容**：苏格拉底式教学不反对给答案，反对的是**过早**给答案。目标从"不给答案"改为"**该问时问、该讲时讲**"——学生已尝试、阶梯已爬到位、或概念澄清完成后，应给出完整答案与讲解。

**已有基础（无需返工的部分）**：
- DPO 计划已写对：`docs/dpo_alignment_plan.md` §目标 —— "第二轮（学生展示尝试后）给出完整代码与讲解，概念类问题照常直答——而不是学成'拒答一切'"
- DPO 数据已对：chosen 层"无错完整讲解"413 条，`G` 层显式不拒答风格 34 对
- 评测指标已对：双指标本来就是两端防刷分（防过早给 + 防过度拒）

**需要修正的部分**：
1. ~~**运行时护栏无时机条件**~~ → **已实现（2026-10-12，时机释放阀落地）**：R1 命中时满足任一条件即**不拦截、不重生成**，放行"参考实现 + 对照讲解"（`severity=released`）：
   - **学生已尝试**：本轮消息围栏代码块有效代码行 ≥3（`RELEASE_MIN_STUDENT_CODE_LINES`，不去重计数）
   - **多轮被拦**：同 user_id + exercise_id 在 `answer_guard_log.jsonl` 累计 blocked ≥2 次（`RELEASE_MIN_BLOCKED_ROUNDS`）
   - 落点：`answer_guard_service.py` 的 `evaluate_release()`；四个调用点（qa 非流式/流式、lab 非流式/流式+持久化兜底）均接入；释放时跳过 `REGEN_FEEDBACK` 注入并前置一句"看到你已有尝试，先对照差异再看讲解"的引导语
   - 日志 channel 区分 `released` / `stream_released` 供评测统计；**评测脚本不传 `release` 参数即保持原拦截行为，历史口径不受影响**
   - mastery 达标释放已落地（第三条件：掌握度 ≥0.7 两证据源取高，无证据不释放，2026-10-13）；剩余与 DPO 训后联调；对外表述用"时机受控释放"而非"释放阀"黑话
2. **对外措辞**：PPT 标题与 P4/P7 的"防泄题"框架改为"答案释放时机管理"（`ppt_structure.md` 已改）
3. **指标命名**：`round2_give_rate` 补人工口径为主报数（规则口径是下界），新增"恰当给码率"叙事——给码率 0.5（人工）在次轮是**优点**不是缺点

**文献支撑（均有 venue）**：**PNAS 2025 Bastani（最高量级：直给答案伤害撤工具后的保持测验，而"教师设计的 hint"型护栏可避免伤害——时机受控释放的直接 RCT 证据）**、ITiCSE 2026 Rubber Duck（置信信号调节保留强度）、Findings ACL 2025 Productive Failure（先挣扎后介入）、CHI 2024 CodeAid（分级释放而非全拒）、ITiCSE 2024 WorkedGen（示例渐退，"何时给"的学习科学依据）
