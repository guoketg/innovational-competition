## （一）产品概述与定位

### 1.1 背景与目标

**行业背景**：AI 代码生成工具已大规模进入开发与学习场景。据公开行业统计，2026 年全球 AI 编程市场规模约 128 亿美元，2024–2030 年复合增长率约 24.5%；IDC 报告显示中国 AI 编程市场 2025 年规模 3.99 亿元，预计 2026 年底增长至 11.73 亿元；全球约 85% 的开发者已在日常工作中使用 AI 编程工具（来源见 §5.2，附录 4）。

**教育痛点**：在编程教学场景中，"能力"与"效率"的矛盾被放大——大模型可以瞬间给出完整可运行的代码，学生的一键获取替代了本应发生的调试、试错与推理。计算机教育共同体近三年的实证研究反复指出这一风险：

- 学生普遍采用 one-shot prompting（一句要完整功能）的求助行为（SIGCSE 2025）；
- 使用 AI 助手后通过率上升但理解未同步增长，出现认知卸载（ICER 2025）；
- 直接给答案的 AI 辅导会伤害学生在撤去工具后的保持测验成绩，而"教师设计的提示"型护栏可避免该伤害（PNAS 2025，RCT）。

**我们的判断（理念定位）**：苏格拉底式教学不反对给答案，反对的是**过早**给答案。系统要控制的不是"给不给"，而是**答案释放的时机**——该问时问、该讲时讲。过早给（基线模型首轮直给率 80%）与过度拒（该给不给）两端都是缺陷。

**研发目标**：构建一个"教学时机对齐"的编程实训大模型应用——用运行时护栏在输出侧强制时机约束，用时机释放阀避免过度拒答，用分层教学策略组织"先引导、后给解"的对话流程，并用分组隔离的评测闭环证明约束有效，最终以 DPO 数据管道把该行为模式向模型权重内化。

### 1.2 产品定位

| 维度 | 定位 |
| --- | --- |
| 产品类型 | AI 赋能教育软件（Web 应用）＋ 教学时机对齐的 LLM 应用系统，属赛题"智能学习插件、智能体、Web AI 应用"明确允许范围 |
| 目标用户 | 高校程序设计/数据结构课程学生（主）、任课教师与助教（次）；可扩展至竞赛集训与自学刷题人群 |
| 核心功能 | AI 对话答疑、CodeLab 编程实验室（在线编码 + C++ 判题 + AI 引导）、学情诊断、RAG 知识库问答、错题本与学习文档 |
| 应用场景 | 课内实训引导、课后作业答疑、考前自测复盘、竞赛刷题过程中的"防抄答案 + 适时讲透" |
| 差异化优势 | ①**时机受控的答案释放**（拦截过早给码、学生尝试后放行完整讲解）；②**可量化的评测闭环**（双口径 A/B + 分组隔离 held-out）；③**全栈本地可复现部署**（docker compose up -d） |

**一句话定位**：面向编程实训的 LLM 教学时机对齐系统——三层护栏 + 分层教学策略 + DPO 数据管道，用评测闭环证明"先引导、后给解；该问时问、该讲时讲"。

### 2.3 创新应用（对比同类产品）

**创新点一：三层护栏的"答案释放时机"约束架构（核心）**

把教育约束做成**输出前的架构级网关**，而非提示词里的一句话：

1. **输入层**：`detect_exercise` 两级关卡识别，判断问题属于哪一关，从而挂载对应参考解；能力画像与敏感输入过滤（规则）。
2. **输出层（运行时 Shield）**：
   - **R1 参考解重叠检测**——回答中的代码块与该关参考解做有效行集合比对，recall ≥ 0.6 且重叠 ≥ 5 行即判"泄题"，拦截并替换为引导话术；
   - **R2 长代码检测**——单块 ≥ 15 行且全篇 ≥ 25 行判"疑似完整实现"；
   - **流式逐块过滤**——不是全量后处理，`GuardedStreamFilter` 在 SSE 生成过程中逐块判定，延迟友好；
   - **重生成再检**——拦截后带 `REGEN_FEEDBACK` 重新生成并二次检测，最多重试。
3. **权重层（DPO 数据管道）**：把"先引导、后给解"的时机行为构建成偏好对，向模型权重内化（管道与质检已完成，见 §4.3）。

**创新点二：时机释放阀——从"防泄题"到"时机受控释放"（差异化亮点）**

只有拦截没有放行会造成"过度拒答"。R1 命中时满足任一条件即**不拦截、不重生成**，放行"参考实现 + 对照讲解"（`severity=released`，`blocked=False`）：

| 释放条件 | 阈值常数 | 含义 |
| --- | --- | --- |
| 学生已尝试 | `RELEASE_MIN_STUDENT_CODE_LINES = 3` | 本轮消息围栏代码块有效代码行 ≥ 3（不去重），即"你动手了，该给你看参考实现了" |
| 多轮被拦 | `RELEASE_MIN_BLOCKED_ROUNDS = 2` | 同 user + 同关卡累计被拦 ≥ 2 次，即"引导已充分，再拦就是刁难" |
| 掌握度达标 | `RELEASE_MIN_MASTERY = 0.7` | 该关卡掌握度估计（工作区阶段状态 `stage_mastery` 与 `knowledge_mastery` 表两证据源取高）≥ 0.7，即"你已达标，参考实现只是对照检验"；无证据按 0 处理 → 不释放 |

释放时跳过重生成注入，前置一句"看到你已经写出自己的版本了——先自己对照参考实现找差异，再看讲解"的引导语；日志 channel 记为 `released`/`stream_released` 供评测统计；评测脚本不传释放参数即保持原拦截行为，历史评测口径不受影响。该机制对应 PNAS 2025（伤害学习的是"过早直给"而非"给答案"本身）与 worked-example fading（示例渐退）的学习科学依据。

**创新点三：分层教学策略（高层动作离散可控）**

高层从 6 种教学动作（teaching moves）中分类选择一个，低层由 LLM 渲染成自然话术（SayCan 式高低分离）——动作空间离散、可解释、可审计，每次决策落库可回放；`mastery_hint_level` 按掌握度给出 hint_level 1–4 阶梯（首轮 ≤3 行提示 → 指行号给概念 → 给根因 → 完整讲解），对应"示例渐退"机制。

**创新点四：评测方法学（评审可核验）**

- **双口径**：规则口径（字符串匹配，下界）+ LLM 裁判口径，交叉印证；
- **双指标**：首轮不给码率（防过早给）+ 次轮给码率（防过度拒），两端防刷分；
- **分组隔离 held-out**：训练关卡 9 个 / 评测关卡 4 个、题族 33/12，评测族不进训练，防泄露；
- **失败案例主动报告**：护栏后残留的 16 例可见直给已逐条归因（14 例护栏未触发的轻量直给 + 2 例讲解复述），不隐藏缺陷。

**与同类产品的差异**：通用编码助手（Copilot/Cursor 等）以"更快写出代码"为目标，本产品以"学生学会"为目标，主动抑制直给；市面 AI 课程助教（如 CodeGeeX 校园版）提供答疑与课程知识库，但公开资料未见"输出侧参考解重叠拦截 + 时机释放"这一层运行时约束与对应的分组隔离评测（竞品对标详见 §5.2）。

- **模型升级接口**：LLM 接入统一为 OpenAI 兼容层，`LLM_MODEL`/`EVAL_BASE_URL`/`EVAL_MODEL` 环境变量即可切换主模型或本地模型（`edu-ta-qwen3-1.7b-local` :8010），DPO 训后模型可直接作为新端点挂入；
- **护栏参数化**：R1/R2 阈值与释放阀两阈值均为模块常数，同一参数框架可扩展 mastery 达标释放等新条件；
- **多技术融合路径**：教学动作分类器、mastery 估计均已独立成服务（`teaching_policy_service`），可替换为置信累积-阈值机制或认知诊断模型而不动业务层；
- **多端扩展**：前后端分离 + JWT，可平移至桌面/移动端或嵌入现有 OJ 平台。

### 4.2 代码实现（关键 AI 功能）

**① 护栏判定核心**（`student/backend/services/answer_guard_service.py`）——对每个代码块与参考解做有效行集合比对，recall 与重叠行数双阈值判定：

```python
def _block_is_leak(block_code: str, ref_sets: list[set[str]]) -> tuple[bool, int, float, int]:
    """对每份参考解求 (重叠, recall)，返回 (命中任一?, 最优重叠, 最优recall, 对应参考解行数)。"""
    if not ref_sets:
        return False, 0, 0.0, 0
    block_lines = _significant_lines(block_code)
    best = (False, 0, 0.0, len(ref_sets[0]))
    for ref in ref_sets:
        overlap = len(block_lines & ref)
        recall = overlap / len(ref)
        if recall >= R1_RECALL_THRESHOLD and overlap >= R1_MIN_OVERLAP_LINES:
            return True, overlap, recall, len(ref)
        if recall > best[2]:
            best = (False, overlap, recall, len(ref))
    return best
```

**② 时机释放阀**——"该不该放行完整讲解"的两条件判定：

```python
RELEASE_MIN_STUDENT_CODE_LINES = 3   # 学生本轮贴出的有效代码行数达到该值 → 释放
RELEASE_MIN_BLOCKED_ROUNDS = 2       # 同用户同关卡累计被拦次数达到该值 → 释放

def evaluate_release(user_id, exercise_id, question: str) -> tuple[bool, str]:
    """返回 (是否释放护栏, 释放原因)；原因 ∈ {"student_attempt", "blocked_rounds", ""}。"""
    if not exercise_id:
        return False, ""
    if count_student_code_lines(question) >= RELEASE_MIN_STUDENT_CODE_LINES:
        return True, "student_attempt"
    if count_blocked_rounds(user_id, exercise_id) >= RELEASE_MIN_BLOCKED_ROUNDS:
        return True, "blocked_rounds"
    return False, ""

def apply_guard(answer, reference_solution="", *, release: bool = False):
    """release=True：即使命中 R1 也不拦截，severity 记为 "released"
    （blocked=False，调用方因此不会触发重生成）。"""
    verdict = evaluate(answer, reference_solution)
    if not verdict.blocked:
        return answer, verdict
    if release:
        verdict.blocked = False
        verdict.severity = "released"
        ...
```

**③ 流式逐块过滤**：`GuardedStreamFilter` 在 SSE 块生成过程中执行同样的判定，支持 `release`/`release_reason`/日志上下文；放行时在首块前补一次释放引导语，日志 channel 记 `stream_released`。四个调用点（qa 非流式/流式、lab 非流式/流式 + 持久化兜底）全部接入。

## （五）应用价值与展望

### 5.1 应用场景

**场景一：课内实训——"先写再看"的闯关引导**
学生在关卡提交有 bug 的代码，AI 不直接改码，而是按 6 教学动作提问定位（TC-03/TC-05 通过，截图留档）。连续多轮后按 hint_level 1–4 逐级给提示；学生贴出自己的代码（≥3 行）或同关卡被拦 ≥2 轮后，系统放行参考实现与对照讲解。**量化**：同一批 30 题上，首轮直接给码率从 80%（规则）/93.3%（裁判）降至 53.3%/80%，长代码输出 3→0。

**场景二：课后答疑——防 one-shot 抄答案**
学生"我赶时间，直接发我改好的代码"式的请求触发 R1 拦截，改为承诺式引导："把你写的版本发给我——我看到你的尝试后，会把参考实现和你的写法对照着讲给你看"。**量化**：held-out 4 关三臂评测中首轮不给码率保持 1.0，且误拒率 0.0（该给时给了）。

**场景三：考前复盘——学情诊断 + 错题本**
诊断报告定位知识盲区，错题本归档，RAG 知识库按课程资料回答概念性问题（概念类问题照常直答，不套用代码护栏）。

**场景四：教师侧价值**
护栏日志 `answer_guard_log.jsonl` 与 `teaching_move_log` 构成全量对话决策审计链，教师可回放"系统何时拦、何时放、为什么"，也可用同一评测脚本复测新模型，作为课程 AI 治理的抓手。

### 5.3 成果总结

**核心成果**：

1. **一个完整可运行的软件产品**：12 路由 130 端点、16 页面、34 服务模块，Docker Compose 一键部署，3 容器合计约 30.1 MiB，通过 129 项单元测试与 9 条端到端功能用例（7 张截图证据）。
2. **一套"答案释放时机"约束架构**：三层护栏（输入识别 → 输出侧 R1/R2 Shield + 流式过滤 + 重生成再检 → 权重层 DPO 管道），并落地**时机释放阀**——三条件（贴码 ≥3 行 / 被拦 ≥2 轮 / 掌握度 ≥0.7）实现"该问时问、该讲时讲"，避免从"过早给"矫枉过正为"过度拒"。拦截路径讲解不缺席：被拦后重生成仍给定位思路、引导提问与部分讲解。
3. **一组可复现的量化证据**：A/B 双口径（直给码 24/30 → 16/30，相对降 33.3%；长代码 3 → 0）、held-out 三臂（首轮不给码率 1.0、误拒 0.0）、DPO 管道质检（871/230 对，泄漏 0.000、违规 0.000）——所有数字可由仓库内 JSON 报告复核。
4. **一条评测驱动的数据管道**：按问题族 70/30 分组隔离防泄露，四层质检矩阵（边界分类/泄漏检测/讲解率/层级呼应），为 DPO 权重内化提供合格弹药。

**关键技术突破与经验**：①把教育约束从提示词升级为**输出前的架构级网关**（可审计、可保证）；②发现"只拦不放"会造成过度拒答并以两阈值机制修复——护栏与释放是一对设计，缺一即失衡；③评测必须双口径双指标并存，单一口径（如规则下界 0.1667 vs 人工 0.5）会误导结论；④失败案例（残留 16 例）的逐条归因比全绿的报告更有说服力。

**诚实边界（已知不足）**：效果证据来自离线评测与人工走查，尚无真实学生的随机对照实验；人工标注 30 条尚未回填（裁判口径暂无人工交叉验证）；held-out 样本量小（每臂 3 runs × 12 样本）；生成与裁判同源（deepseek-chat）存在同源偏差；DPO 训练已完成但初评判定奖励黑客，"何时给代码"条件策略尚未验证（详见 DPO 运行总结 §四）。

### 5.4 未来规划

**近期（功能完善，1–3 个月）**：
1. **回填人工标注**：完成 30 条人工核验，输出裁判-人工一致率，闭合双口径验证的最后一环；
2. **扩大评测样本与分层报告**：held-out 增加 runs 与关卡数，按数据层（含 97 对越狱话术 X 层）分解报告，对标对抗泄漏鲁棒性评测；
3. **残留直给治理**：针对 14 例轻量直给收紧 R1 判据（引入语义相似度补充行重叠），针对 2 例"讲解复述"增加讲解侧修复点复述检测；
4. **mastery 达标释放（已落地）**：释放阀第三条件——掌握度估计 ≥0.7 即放行（工作区阶段状态与 knowledge_mastery 表两证据源取高，无证据按 0 → 不释放，向后兼容），复用现有参数框架（RELEASE_MIN_MASTERY 模块常数）；剩余为与 DPO 训后模型联调。

**中期（算法升级与验证）**：
5. **DPO → IPO 权重对齐重跑**：首轮 DPO 已训完但判定奖励黑客（460:19 数据不对称为主因）；先扩 boundary(C) 正样本、降 β/加早停，再以 IPO（AISTATS 2024，TRL 一行切换）重跑，并在 held-out 上做 base vs 对齐模型的**分层行为对照评测**（boundary 给码 / redteam 拒绝 / socratic 提示）验证"时机行为内化进权重"；
6. **学习成效指标**：引入无辅助保持测验（脱机前后测）与 help-seeking 行为编码，把评测从"释放行为"推进到"学习增益"；
7. **机制升级**：`stage_mastery → hint_level` 由 if-else 启发式升级为置信累积-阈值机制，使阶梯决策有文献先例支撑。

**远期（场景拓展）**：
8. **多端与平台集成**：VS Code 插件 / OJ 平台对接，覆盖学生已有工具链；
9. **教师端与课程治理**：护栏审计面板、班级维度的依赖度/试错度画像，从"学生工具"扩展为"课程 AI 治理平台"；
10. **多语言与多学科**：判题与参考解体系从 C++ 扩展到 Python/Java，引导策略迁移到数学、电路等"有标准解但重过程"的学科。

**风险与应对**：模型同源偏差 → 引入异源裁判模型与人工抽检；样本量不足 → 扩大 held-out 并做显著性检验；数据隐私 → 行为日志本地存储、密钥不入库，符合赛题合规要求。
