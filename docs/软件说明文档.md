## （一）项目背景

### 1.1 行业背景

AI 代码生成工具已大规模进入开发与学习场景。据公开行业统计，2026 年全球 AI 编程市场规模约 128 亿美元，2024–2030 年复合增长率约 24.5%；IDC 报告显示中国 AI 编程市场 2025 年规模 3.99 亿元，预计 2026 年底增长至 11.73 亿元；全球约 85% 的开发者已在日常工作中使用 AI 编程工具（来源见 §5.2，附录 4）。

### 1.2 教育痛点

在编程教学场景中，"能力"与"效率"的矛盾被放大——大模型可以瞬间给出完整可运行的代码，学生的一键获取替代了本应发生的调试、试错与推理。计算机教育共同体近三年的实证研究反复指出这一风险：

- 学生普遍采用 one-shot prompting（一句要完整功能）的求助行为（SIGCSE 2025）；
- 使用 AI 助手后通过率上升但理解未同步增长，出现认知卸载（ICER 2025）；
- 直接给答案的 AI 辅导会伤害学生在撤去工具后的保持测验成绩，而"教师设计的提示"型护栏可避免该伤害（PNAS 2025，RCT）。

### 1.3 设计理念：不反对给答案，反对过早给答案

苏格拉底式教学不反对给答案，反对的是**过早**给答案。系统要控制的不是"给不给"，而是**答案释放的时机**——该问时问、该讲时讲。过早给（基线模型首轮直给率 80%）与过度拒（该给不给）两端都是缺陷。

由此确定研发目标（分两层）：

- **基础盘（产品成立的前提）**：做一个扎实的计算机学科（数据结构与算法等）实训教学软件——"学（知识库/学习资料）—练（关卡判题）—测（学情诊断/自测）—复习（错题本/间隔复习）"完整学习闭环必须齐全好用，这是评委判断"是一个基本的软件"的依据。
- **亮点层（锦上添花的差异化）**：在基础之上叠加**教学时机对齐**能力——用运行时护栏在输出侧强制时机约束，用时机释放阀避免过度拒答，用分层教学策略组织"先引导、后给解"的对话流程，并以 DPO 数据管道把该行为模式向模型权重内化。亮点层的价值在于让评委看到"我们和别人不一样"，但不替代基础盘。

### 1.4 产品定位

| 维度 | 定位 |
| --- | --- |
| 产品类型 | AI 赋能教育软件（Web 应用） |
| 产品分层 | **基础**：计算机学科（数据结构与算法等）实训教学软件——学练测复习闭环齐全是底座；**亮点**：教学时机对齐（动态护栏 + 苏格拉底式分层引导），锦上添花的差异化 |

## （三）技术创新

### 3.1 创新点一：三层护栏的"答案释放时机"约束架构（核心）

把教育约束做成**输出前的架构级网关**，而非提示词里的一句话：

1. **输入层**：`detect_exercise` 两级关卡识别，判断问题属于哪一关，从而挂载对应参考解；能力画像与敏感输入过滤（规则）。
2. **输出层（运行时 Shield）**：
   - **R1 参考解重叠检测**——回答中的代码块与该关参考解做有效行集合比对，recall ≥ 0.6 且重叠 ≥ 5 行即判"泄题"，拦截并替换为引导话术；
   - **R2 长代码检测**——单块 ≥ 15 行且全篇 ≥ 25 行判"疑似完整实现"；
   - **流式逐块过滤**——不是全量后处理，`GuardedStreamFilter` 在 SSE 生成过程中逐块判定，延迟友好；
   - **重生成再检**——拦截后带 `REGEN_FEEDBACK` 重新生成并二次检测，最多重试。
3. **权重层（DPO 数据管道）**：把"先引导、后给解"的时机行为构建成偏好对，向模型权重内化（管道与质检已完成，训练尚未通过验收，见 §4.3）。

### 3.2 创新点二：时机释放阀——从"防泄题"到"时机受控释放"（差异化亮点）

只有拦截没有放行会造成"过度拒答"。R1 命中时满足任一条件即**不拦截、不重生成**，放行"参考实现 + 对照讲解"（`severity=released`，`blocked=False`）：

| 释放条件 | 阈值常数 | 含义 |
| --- | --- | --- |
| 学生已尝试 | `RELEASE_MIN_STUDENT_CODE_LINES = 3` | 本轮消息围栏代码块有效代码行 ≥ 3（不去重），即"你动手了，该给你看参考实现了" |
| 多轮被拦 | `RELEASE_MIN_BLOCKED_ROUNDS = 2` | 同 user + 同关卡累计被拦 ≥ 2 次，即"引导已充分，再拦就是刁难" |
| 掌握度达标 | `RELEASE_MIN_MASTERY = 0.7` | 该关卡掌握度估计（工作区阶段状态 `stage_mastery` 与 `knowledge_mastery` 表两证据源取高）≥ 0.7，即"你已达标，参考实现只是对照检验"；无证据按 0 处理 → 不释放 |

释放时跳过重生成注入，前置一句"看到你已经写出自己的版本了——先自己对照参考实现找差异，再看讲解"的引导语；日志 channel 记为 `released`/`stream_released` 供评测统计；评测脚本不传释放参数即保持原拦截行为，历史评测口径不受影响。该机制对应 PNAS 2025（伤害学习的是"过早直给"而非"给答案"本身）与 worked-example fading（示例渐退）的学习科学依据。

### 3.3 创新点三：以"教学"为第一性的分层教学策略

本产品是教学软件，技术创新必须能落到"怎么教"上，而不只是"怎么拦"。为此把教学行为建模成**离散、可控、可审计**的两层结构：

- **高层教学动作（6 种 teaching moves）**：由策略服务分类选择一个动作（如澄清、追问、给提示、给参考实现等），动作空间离散、可解释、可审计，每次决策落库 `teaching_move_log` 可回放；
- **低层话术渲染**：高层定动作、低层由 LLM 渲染成自然语言（SayCan 式高低分离），避免"提示词即策略"的不可控；
- **掌握度驱动的提示阶梯**：`mastery_hint_level` 按掌握度给出 hint_level 1–4 阶梯——首轮 ≤3 行提示 → 指行号给概念 → 给根因 → 完整讲解，对应学习科学的"示例渐退"（worked-example fading）：掌握度越高，提示越直接、越接近完整讲解；
- **教学不因拦截而缺席**：被拦后重生成仍给定位思路、引导提问与部分讲解，而不是一句"我不能帮你写代码"。

该创新点体现"作为教学软件要体现出教学"的定位：不是简单地拒绝回答，而是按学生的实际尝试程度与掌握水平，动态调整教学的深浅与时机。

### 3.4 创新点四：评测方法学（评审可核验）

- **双口径**：规则口径（字符串匹配，下界）+ LLM 裁判口径，交叉印证；
- **双指标**：首轮不给码率（防过早给）+ 次轮给码率（防过度拒），两端防刷分；
- **分组隔离 held-out**：训练关卡 9 个 / 评测关卡 4 个、题族 33/12，评测族不进训练，防泄露；
- **失败案例主动报告**：护栏后残留的 16 例可见直给已逐条归因（14 例护栏未触发的轻量直给 + 2 例讲解复述），不隐藏缺陷。

### 3.5 创新边界：工具调用（行为）通道尚未覆盖（如实说明）

上述三层护栏约束的是**内容通道**——即评判"AI 的文本回复是否给出了可运行修复"。但生成式教学助手还存在一条更隐蔽的**行为通道**：AI 通过工具调用**直接把学生的代码改好**（IDE Agent 常见形态），学生连"答案"都不用看代码就被改完了，反而更学不到东西。

**当前状态：这一通道尚无任何护栏、样本或标注**。现有评测（A/B 护栏、LLM 裁判、30 条人工核验表）全部为文本响应快照，只覆盖内容通道；DPO 数据也仅为纯文本 chosen/rejected 偏好对，模型只学"说不说码"、不学"走哪条通道（引导 / 给码 / 改码）"。补齐该通道的方案已规划（三工具决策：`give_hint`/`give_answer`/`modify_code`），列入 §5.5 未来规划，属下一阶段工作。

### 3.6 与同类产品的差异

通用编码助手（Copilot/Cursor 等）以"更快写出代码"为目标，本产品以"学生学会"为目标，主动抑制直给；市面 AI 课程助教（如 CodeGeeX 校园版）提供答疑与课程知识库，但公开资料未见"输出侧参考解重叠拦截 + 时机释放"这一层运行时约束与对应的分组隔离评测（竞品对标详见 §5.2）。

## （五）总结展望

### 5.1 应用场景

**场景一：课内实训——"先写再看"的闯关引导**
学生在关卡提交有 bug 的代码，AI 不直接改码，而是按 6 教学动作提问定位（TC-03/TC-05 通过，截图留档）。连续多轮后按 hint_level 1–4 逐级给提示；学生贴出自己的代码（≥3 行）、同关卡被拦 ≥2 轮、或掌握度估计 ≥0.7 三条件之一满足时，系统放行参考实现与对照讲解。**量化（行为层）**：同一批 30 题上，首轮直接给码率从 80%（规则）/93.3%（裁判）降至 53.3%/80%，长代码输出 3→0。

**场景二：课后答疑——防 one-shot 抄答案**
学生"我赶时间，直接发我改好的代码"式的请求触发 R1 拦截，改为承诺式引导："把你写的版本发给我——我看到你的尝试后，会把参考实现和你的写法对照着讲给你看"。**量化（行为层）**：held-out 4 关三臂评测中首轮不给码率保持 1.0，且误拒率 0.0（该给时给了）。

**场景三：考前复盘——学情诊断 + 错题本**
诊断报告定位知识盲区，错题本归档，RAG 知识库按课程资料回答概念性问题（概念类问题照常直答，不套用代码护栏）。

### 5.3 成果总结

**核心成果**：

1. **一个完整可运行的软件产品**：12 路由 130 端点、16 页面、34 服务模块，Docker Compose 一键部署（2 服务），内存占用受控（实测见 §2.6），通过 129 项单元测试与 9 条端到端功能用例（7 张截图证据）。
2. **一套"答案释放时机"约束架构**：三层护栏（输入识别 → 输出侧 R1/R2 Shield + 流式过滤 + 重生成再检 → 权重层 DPO 管道），并落地**时机释放阀**——三条件（贴码 ≥3 行 / 被拦 ≥2 轮 / 掌握度 ≥0.7）实现"该问时问、该讲时讲"，避免从"过早给"矫枉过正为"过度拒"。拦截路径讲解不缺席：被拦后重生成仍给定位思路、引导提问与部分讲解。
3. **一组可复现的量化证据（行为层）**：A/B 双口径（直给码 24/30 → 16/30，相对降 33.3%；长代码 3 → 0）、held-out 三臂（首轮不给码率 1.0、误拒 0.0）、DPO 管道质检（871/230 对，泄漏 0.000、违规 0.000）——所有数字可由仓库内 JSON 报告复核。
4. **一条评测驱动的数据管道**：按问题族 70/30 分组隔离防泄露，四层质检矩阵（边界分类/泄漏检测/讲解率/层级呼应），为 DPO 权重内化提供合格弹药。

**关键技术突破与经验**：①把教育约束从提示词升级为**输出前的架构级网关**（可审计、可保证）；②发现"只拦不放"会造成过度拒答并以两阈值机制修复——护栏与释放是一对设计，缺一即失衡；③评测必须双口径双指标并存，单一口径（如规则下界 0.1667 vs 人工 0.5）会误导结论；④失败案例（残留 16 例）的逐条归因比全绿的报告更有说服力。

### 5.4 诚实边界（已知不足）

1. **教学成效未验证**：效果证据仅到"行为层离线评测"，尚无真实学生的随机对照实验（§4.3）。
2. **人工标注未回填**：30 条核验表尚未标注，裁判口径暂无人工交叉验证。
3. **样本量小且同源偏差**：held-out 样本量小（每臂 3 runs × 12 样本）；生成与裁判同源（deepseek-chat），存在同源偏差。
4. **DPO 训练未通过验收**：判定奖励黑客，"何时给代码"条件策略尚未验证。
5. **行为通道仅有规则口径基线，真实口径待补**：AI 直接改码的行为通道产品侧已有 Shield + 释放阀（§3.5），评测侧本轮新增**规则口径基线**（20 条用例 + `scripts/evaluate_behavior_channel.py`，方案 C + 请求轴：明确改码请求→提示 1 次后放行（作业催促也触发）、核心违规=未请求主动改）；但该基线**只镜像护栏规则、不度量模型真实行为**，真实轨迹 shadow replay（`--from-log`）与真人实测仍待补（详见 §4.3）。

11. **多语言与多学科**：判题与参考解体系从 C++ 扩展到 Python/Java，引导策略迁移到数学、电路等"有标准解但重过程"的学科。

**风险与应对**：模型同源偏差 → 引入异源裁判模型与人工抽检；样本量不足 → 扩大 held-out 并做显著性检验；数据隐私 → 行为日志本地存储、密钥不入库，合规可控。
