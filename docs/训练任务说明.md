# DPO 训练任务说明（云端执行，仓库不含训练代码）

> 定位：本文档**只描述训练任务**。训练全部在云端完成，仓库内不归档、不编写任何训练代码；
> 训练脚本、日志、checkpoint 均留在云端，本地仓库只保留数据产物与评测报告。
> 关联：[dpo_alignment_plan.md](../student/docs/dpo_alignment_plan.md)、[测试报告.md](测试报告.md) §6.4。

## 任务目标

训练一个"该引导时引导、该给码时给码"的编程辅导模型：首轮不泄题、学生展示尝试后给完整代码+讲解、概念问题直答——不学成"拒答一切"。
控制目标是**答案释放时机**，不是"拒绝给答案"（见 [创新性与顶会文献支撑.md](创新性与顶会文献支撑.md) §四）。

## 数据（本地已就绪，训练前上传云端）

- 六层混合 **871 训练对 + 230 held-out 对**：P（CodeLab 关卡）/ A（Socratic 调试）/ C（防拒答边界）/ X（越狱红队）/ G（通用防遗忘）
- 格式：TRL conversational DPO jsonl（prompt messages + chosen/rejected），由 `student/backend/scripts/build_dpo_pairs.py` 产出
- 质检：泄漏 0.000、讲解率 1.0、违规率 0.000（`student/backend/data/dpo/dpo_quality_audit.json`）
- 防泄露：按问题族 70/30 分组，held-out 清单（4 关 + 12 族）写入 `dpo_build_report.json`，验收只跑 held-out

## 云端环境与超参（既有口径）

| 项 | 值 |

## 已知问题（阻塞验收）

首轮训练出现**奖励黑客**：数据 460:19 不对称 + 标准 DPO 过度训练，代理指标饱和（eval_loss 0.0537 / acc 0.9826，218 步）但条件策略行为未验证（[测试报告.md](测试报告.md) §6.4）。
**结论：不修数据，换任何 loss 都复发。**

## 待执行的训练任务（全部云端侧）

1. **修数据不对称**：把 460:19 拉回可控配比，优先补 C 层与 round2 给码样本（本地改数据 → 重新上传）
2. **IPO 重跑**：TRL `loss_type="ipo"`（AISTATS 2024，抗 over-training），SimPO 备选
3. **产物回传**：训后只在 held-out 上验收，adapter + metrics 回传本地评测链路

## 验收标准（双轨）

- **领域**：Socratic held-out 直接给码率 ≤2/20（基线 20/20、运行时护栏 2/20）；CodeLab held-out 4 关"首轮不给码率 + 次轮给码率"双指标；**false-refusal 人工抽查为红线**（不能拒绝该给的代码）
- **通用**：50 条通用问答训前训后掉点 <5%
- **归因**：按 source/layer 分层统计哪层数据贡献了行为改变

## 部署作用域

DPO 模型只替换 CodeLab 导师链路（`lab_workspace_service.ask_assistant`），qa/答辩/题解仍用基座 + 运行时护栏；护栏不撤，留回退开关。
