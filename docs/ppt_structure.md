### P1 封面

- 副标题挂三个可引用词：**运行时护栏（Shielding, AAAI'18）· DPO（NeurIPS'23）· 分层教学策略（SayCan 式）**
- 队伍/赛道/日期

### P2 问题与痛点
- 核心信息：LLM 直接替学生写代码 → 实训教学失效
- 数据点：本项目基线评测（deepseek-chat，30 道实训题）中，模型**直接给出修复代码 24/30（80%，规则口径下界）/ 28/30（93.3%，LLM 裁判口径）**，另有 3 例输出 ≥15 行大段代码
- 数据来源：`backend/data/eval/direct_code_rate_report.json` → `summary.baseline`（规则口径）；`llm_judge_report.json` → `summary.by_arm.baseline`（裁判口径）
- **背景加严（行为通道，2026-10-14）**：LLM 甚至**未经学生要求主动改代码**——学生只问"这里为什么错"，agent 顺手把 bug 修了（开发者实测踩坑）。认知卸载的极端形式：one-shot prompting 卸载的是"想"，代改卸载的是"做"——学生连"报错→定位→修→再跑"的调试闭环都没经历，程序性技能零练习。对照 PNAS 2025（伤害学习的不是"给答案"而是"过早直给"）：行为通道 = "过早代改"，危害更重一层。**我们的立场：不禁止改代码，而是"在合适时机改"**（详见进度表 #35 / dpo §3.10 判定规则修订）
- 讲稿：一次真实助教场景的截图/对话示例（学生说"我赶时间，直接发我改好的代码"）

### P3 总体架构

- 要点：**先讲底座，再讲亮点**（2026-10-13 定位复核）。
  - **(a) 底座：学练测复习闭环**——学（RAG 知识库问答 + 98 篇学习资料，4887 分块混合检索）、练（CodeLab 13 关旗舰关 + C++/Python 判题 + AI 引导）、测（学情诊断 600 题四步画像 + 自测）、复习（错题本 + 间隔复习），AI 对话答疑贯穿全程——这是"一个功能齐全的计算机学科实训软件"的证据，先立住。
  - **(b) 亮点：教学时机对齐**——左：三层护栏总览（规则 R1–R4 → 运行时 RAG 重叠拦截 → 裁判模型语义判给）；右：6 步骤教学编排（PDCA：teaching_move / (hint_level, mastery)、终轮 LLM 增补、persona 总控、prompt 渐进降级、ReAct 证据链路由、sandbox 复核）；下：两条释放路径（学生尝试 ≥3 行 / 被拦 ≥2 轮 / 掌握度 ≥0.7 → 参考解对照讲解；无参考解 → 引导式再生成 2 轮后放行）。
- 图：自绘两栏——左栏"学习闭环底座"（六模块关系图），右栏"护栏 + 教学编排"（三层护栏总览 + 时机释放），或用 docker_compose_architecture.drawio 扩展。

- 对应结构：见 `docs/软件说明文档.md` §2–§4 全部（本页为总纲）。

### P4 形式化框架（包装页，零成本顶会语言）
- 把系统叙述为 **约束 POMDP**：状态 = 对话历史 + 学习者掌握度画像；动作 = 六步编排的教学动作选择；约束 = 答案释放时机边界（R1/R2：过早释放即拦，时机未到不给完整解；时机成熟放行——不是拒答）
- 三个词各对应一条研究线：约束满足（约束规划/安全过滤）+ 状态估计（知识追踪谱系，related work 身份）+ 策略选择（SayCan 分层）
- 图：一个 POMDP 环形示意图，标注本系统的对应模块
- **红线**：只说"形式化视角"，不说"我们求解了 POMDP"

### P5 核心创新一：三层护栏（数字页）
- 主数字（双口径）：
  - **规则口径（fix_targets 字符串匹配，下界）：基线直给码 24/30（80%）→ 护栏后可见直给码 16/30（53.3%），相对下降 33%**
  - **LLM 裁判口径（LLM-as-a-judge）：基线 28/30（93.3%）→ 护栏后 24/30（80%）**
  - 共同项：**护栏触发 12/30，长代码 3 → 0**
  - 来源：`backend/data/eval/direct_code_rate_report.json` → `summary` / `reduction`（规则）；`llm_judge_report.json` → `summary.by_arm`（裁判）
  - 口径备注（答辩备用）：30 题 × 1 轮，deepseek-chat 真实模型响应 + 真实护栏判据，两臂同一 prompt 集对照；规则-裁判一致率 48/60（80%），不一致 12 条全部为规则保守侧漏检、0 误检
- 三个框：运行时拦截（即时可用）→ DPO 内化（训后生效）→ 裁判仲裁（质检闭环）
- 引用：Shielding（Alshiekh et al., AAAI 2018）；DPO（Rafailov et al., NeurIPS 2023）

### P6 运行时 Shield 技术细节
- R1 参考解重叠检测：输出与关卡参考解做重叠度计算，超阈值拦截
- R2 苏格拉底风格边界判据
- **流式过滤**：响应生成过程中逐块判定，不是全量后处理（延迟友好）
- **时机释放阀（差异化亮点）**：R1 命中但满足任一条件 → 不拦截不重生成，放行"参考实现 + 对照讲解"——① 学生本轮已贴出 ≥3 行自己的代码（已尝试）；② 同用户同关卡累计被拦 ≥2 轮（该给了）；③ 学生在该关掌握度估计 ≥0.7（常量 `RELEASE_MIN_MASTERY`，工作区阶段状态与 knowledge_mastery 表双证据源取高、无证据按 0 不释放）。`evaluate_release` 已落地，36 条单测全过（2026-10-13，进度表 #9）。对应 PNAS 2025 Bastani：伤害学习的不是"给答案"本身而是"过早直给"；worked-example fading（ITiCSE 2024）的"何时给"科学依据
- 拦截后行为（未释放时）：替换为引导话术"请先自己写出关键步骤（哪怕不完整），把你写的版本发给我——我看到你的尝试后，会把参考实现和你的写法对照着讲给你看"（示例截图）；释放时前置"看到你已经写出自己的版本了——先自己对照参考实现找差异，再看讲解"引导语
- 数据点：护栏触发 12/30，但护栏处理后仍残留 16 例可见直给（规则口径）的失败模式分析——**14 例护栏未触发**（重叠度低于阈值的"轻量直给"，`guard_severity: ok`）+ **2 例代码块被拦但讲解仍复述修复内容**（`guard_severity: full` 但 `fix_targets` 命中）——**主动讲失败案例反而显可信**
- **意图机制（判代价不判真伪）**：意图不可从单条文本判定（可伪装、混合、时变），故不判"人"——**默认学习模式** + **显式逃生门**：学生明确声明"工作项目/快速任务"才退出释放阀，但**触发与后续每一次代改全部留痕进学习报告（老师可见）**，作弊成本从"零"变为"可审计留痕"。意图置信度用行为信号（工作区提交痕迹/提问句式/掌握度画像）而非文本声明。诚实边界："我们不承诺识别意图真伪——我们让作弊成本 ≥ 学习成本，且每一次放行可审计"（详见 dpo_alignment_plan §3.10 意图识别框架）

### P8 分层教学策略（SayCan 式高低分离）

### P10 评测方法学（评审最认的一页）
- 评测腿：
  1. **分组隔离 held-out**：按问题族 70/30 切分，评测族不进训练
  2. **A/B 对照（护栏递进对照）**：**四臂**——`raw` 零护栏基线（不带 system prompt 的模型裸输出）/ `baseline` 仅靠 system prompt 底线规则 / `guarded` 再加 `answer_guard` 工具级过滤 / `guarded_regen` 再加有界重生成；`summary.guardrail_lift` 分离两类价值：**raw→baseline 度量 prompt 护栏价值，baseline→guarded 度量工具级护栏边际增益**（早期三臂均带同一 system prompt，度量的其实是"工具级护栏叠在 prompt 护栏之上"的叠加边际增益）。**raw 臂代码就绪、实跑待 `EVAL_API_KEY`，现有报告仍为三臂数据**；另一独立的"真·零护栏"基线在苏格拉底调试基准（n=30，直给 80% → 加护栏 53.3%）
  3. **LLM-as-a-judge**：本地裁判 + 20% 人工抽检校准
  4. **双指标**（CodeLab）：首轮不给码率（防过早给）+ 次轮给码率（防过度拒）——过早给与该给不给都是缺陷
  5. **第三指标·恰当给码率**（叙事收口）：该给时给了 + 不该给时没给的联合口径 =（首轮不给码率 + 次轮给码率）/ 2；规则口径三臂均 **0.5834**（=（1.0 + 0.1667）/2，下界），人工口径待 30 条标注回填后出数（`human_verification.csv`）。**如实说明**：三臂三项主指标全同（首轮不给码率 1.0 / 次轮给码率 0.1667 / 恰当给码率 0.5834）——在该 4 关 held-out 上 prompt 底线规则已把首轮压到天花板，**工具级护栏的边际增益为 0**，其价值体现为次轮 false-refusal 0.0（未引入过度拒答）；工具级护栏的实证增益见苏格拉底基准（直给 80%→53.3%）
  6. **第六条腿（待补，进度表 #35）·行为通道拦截评测**：前五条腿全测"AI 说了什么"（内容通道），这一条测"学生做了什么"——**恰当代改率（双侧，方案 C）** = 该放的放了（学习场景学生**明确要求代改 → 提示 1 次后放行** + 工具性使用逃生门直接放行）+ 该拦的拦了（**未提出任何请求却主动代改**），与恰当给码率对称；配意图三类上下文（学习/工具性使用/伪装）× intent→tool 路由错误率（未请求主动改 / 引导被升格执行）。规则口径基线已出数（方案 C），真实口径（影子回放/微调模型）待补后入 P12
- 基准规模：苏格拉底调试 150 题基准 + 30 题护栏 A/B 对照（deepseek-chat 真实响应）；CodeLab held-out 四臂（raw/baseline/guarded/guarded_regen，raw 臂实跑待 `EVAL_API_KEY`）双指标——首轮不给码率 1.0 / 次轮给码率 0.1667（规则下界，人工抽检近似给码 6/12=0.5，runs=3；`backend/data/eval/codelab_heldout_report.json`）；CodeLab 13 关（9 训练/4 隔离）
  - **待补素材（进度表 #5）**：X 层对抗攻击覆盖对照（held-out 中 X 层越狱单列成列，对标 ACL 2026 Answer Leakage benchmark）——评测数据未跑，出数后补入本页与 P12
  - **待补素材（进度表 #35）**：行为通道评测规则口径基线已出数（方案 C，`backend/data/eval/behavior_channel_report.json`）——20 条用例（学习 13 / 工具性使用 3 / 伪装 2 + BC-19 阴性对照与 BC-20 同回合转明确请求；该放 13 / 该拦 7），恰当代改率 **0.4**、**未请求主动代改率 0.4286**、过度拦截率 **0.6923**、intent→tool 路由错误率 **0.15**、提示 1 次后放行预期 **8**；基线暴露三缺口："无意图逃生门"（工具性使用被误拦）、"无提示 1 次后放行通道"（学习场景已明确要求代改仍被一律拦截）、"规则口径读不到意图"（静默粘贴被误放）。真实口径（影子回放/微调模型）与轨迹级项待补，出数后补入 P12
