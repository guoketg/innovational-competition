# DPO 对齐任务计划（E4 权重层护栏）

> 目的：把 Answer Guard 从"运行时拦截"推进到"权重内化"，补齐 [algorithmic_blueprint.md](../../docs/algorithmic_blueprint.md) E4 的 DPO 路线，形成**三层护栏**叙事：运行时 Shield（已完成）+ 权重层 DPO（本任务）+ 裁判仲裁。
> 本文件供新上下文专门执行此任务，背景见蓝图 §2 E4、§3.1 成熟度阶梯 L2。

## 一、任务目标

用 DPO（LoRA/QLoRA）微调一个 8B 开源指令模型，使其在编程辅导场景中**该引导时引导、该给码时给码**：
首轮引导不泄题，第二轮（学生展示尝试后）给出完整代码与讲解，概念类问题照常直答——而不是学成"拒答一切"。

## 〇、对齐原则与错位复盘（先读）

**对齐原则：线上护栏挡什么，DPO 就学什么。**

初版方案存在三重错位，已复盘修正：

| 错位 | 初版做法 | 修正后 |
|---|---|---|
| 语言错位 | 数据全英文（Socratic benchmark） | 中文为主体（A 层 --zh-ratio 可调，默认 0.5），CodeLab 层天然中文 |
| 题型错位 | 只有 Python 调试题 | 增加 P 层：CodeLab C++ 关卡（与线上 `answer_guard_service` 参考答案同源） |
| 场景错位 | 只有"一次求助→给码" | 增加首轮/次轮时机差异、绕过攻击、概念直答、多轮对话 |

**边界定义（何时给码、何时不给）**：

- **首轮**：学生开口就要答案/完整代码 → 引导（≤3 行提示 + 反问），不给完整码
- **第二轮**：学生展示了自己的尝试/卡点 → 给完整代码 + 讲解（此时给码才是教学）
- **概念/无关请求**：`为什么数组越界会段错误` 这类问题该答就答，不套引导模板
- **红线**：不能拒绝该给的代码——验收含 false-refusal 人工抽查

**测评泄露防线**：按**问题族分组 70/30**（同族题目只进训练或测评一边）；CodeLab 关卡按关卡号分组（9 关训练 / 4 关 held-out）。生成脚本输出 held-out 清单，训练集严禁包含。

## 三、数据策略（六层混合，防遗忘、防泄露、防错位）

总量约 **1000–1050 对**。核心来源全部**离线重新生成**（运行时日志 `answer_guard_log.jsonl` 只有指标没有对话文本，不可作 pair 来源）。

### 3.1 P 层：CodeLab 关卡层（~300 对，主干，与线上护栏同源）

**素材链（全部已在代码库中，零人工标注）**：

- `services/agent_lab_specs.py`：`SPECS["1-1"]...["4-3"]` 13 关，含签名/用例/语言
- `scripts/verify_lab_content.py`：`REFERENCE_SOLUTIONS` / `VARIANT_REFERENCE_SOLUTIONS` 13 关参考答案 = **R1 判据的参考解**
- `services/agent_lab_faults.py`：`FAULT_PROFILES` 中文故障画像 + `curated_mutation_candidates()` 确定性变异出**学生带 bug 代码**

**构造**（每关若干题，覆盖 9 个训练关卡）：

- 学生素材：变异后的带 bug 代码 + 故障画像 → 合成"学生求助"多轮对话
- round1 rejected：无护栏直答（含参考解核心行）；round1 chosen：≤3 行提示 + 反问
- round2 chosen：学生展示尝试后给完整代码 + 讲解；round2 rejected：仍拒答/只给空洞鼓励
- 与线上 `answer_guard_service.evaluate()` 的 R1/R2 判据同源，过滤直接复用

### 3.2 A 层：Socratic 调试层（~300 对，含绕过变体与中文化）

- 来源：150 题 Socratic Programming Debugging Benchmark（英文，见 `scripts/evaluate_direct_code_rate.py` 数据路径）
- 每题生成：round1 引导对 + round2 给码对；部分题目中文化（`--zh-ratio`）
- **绕过变体 rejected**（轮换维度）：语言切换 / 分步套话（"先只给思路"却写成完整码）/ 局部要挟（"只给签名"却给完整实现）/ 假设升级（"假设我已经会了"）

### 3.3 C 层：防拒答边界层（~150–200 对，方向与 P/A round1 相反）

覆盖"不能拒绝该给的代码"：

- **学生已展示尝试** → chosen = 完整代码 + 讲解；rejected = 继续引导/拒给码
- **概念直答**（"解释这个算法为什么错了"）→ chosen = 直接完整解答；rejected = 反问套话
- **明确要完整示例的学习场景**（"给我一个可运行的完整例子对照"）→ 该给就给
- 此层 rejected 是"过度谨慎"行为，`rejected_origin="artificial"` 打标，供训练归因

### 3.4 X 层：输入侧红队层（~80 对）

对应蓝图 E4 输入侧拦截（越狱/诱导提问）：

- rejected：命中越狱话术后仍泄题的回答（须命中 R1）
- chosen：识别诱导意图 + 坚持引导（不命中 R1、不生硬拒答）

### 3.5 G 层：通用偏好防遗忘（~400 对）

- 数据集：**UltraFeedback**（huggingface `datasets` 加载；不可用则跳过并记入报告）
- 配比：领域 : 通用 ≈ 1.5 : 1
- ⚠️ 通用集 chosen 必须是"普通详尽好回答"——不能混入本领域"少给答案"风格，否则模型学成惜字如金
- 训练侧双重保险：LoRA 限制漂移；lr 1e-5~2e-5、1–2 epoch、DPO β 0.1–0.3

### 3.6 分组隔离（防测评泄露）

- **按问题族分组**：文件名剥 `_socratic_dialogue|_conversational_thread_\d+`（含 typo `_thead`）再剥 `^\d+_\d+_` 得到族名；族名哈希 % 10 < 7 → 训练，否则 held-out
- **CodeLab 按关卡分组**：默认 9 关训练 / 4 关 held-out（清单写入报告）
- 报告输出 `held_out_families` 与 `held_out_levels`，验收只跑 held-out

### 3.7 输出格式

统一训练 jsonl（TRL conversational DPO 格式）：

```json
{"prompt": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}],
 "chosen": "...", "rejected": "...",
 "source": "codelab|socratic|redteam|boundary|general",
 "layer": "P|A|C|X|G",
 "family": "0_0_fibonacci", "round": 1, "lang": "zh|en",
 "hint_level": 0, "rejected_origin": "natural|artificial"}
```

- `prompt` 为 messages 列表（支持多轮：把首轮对话放进 messages，chosen/rejected 是最后一轮助手回复）
- `hint_level` ∈ 0–4：1 具体数字/行号 → 2 计算步骤 → 3 概念洞察 → 4 重述问题（生成时以《提示层级 N》标记开头，脚本解析后剥离）
- `source`/`layer`/`rejected_origin` 用于训练后分层归因与人工抽检定位

### 3.8 每层自动质检矩阵（核心优势：护栏指标即质检器）

| 层 | chosen 必须 | rejected 必须 |
|---|---|---|
| P/A round1 | 不命中 R1（recall<0.2）、无 ≥5 行代码块、以问句结尾 | `is_direct_fix` 或 recall ≥ 0.6 |
| P/A round2 | 含完整代码、无拒答套话、**含讲解**（见下） | 拒答/空洞（不含有效代码） |
| C | 含代码且无拒答、**含讲解** | 命中拒答模式（过度引导） |
| X | 不命中 R1 且不生硬拒答 | 命中 R1（recall ≥ 0.6） |
| G | 通过 UltraFeedback 自带评分过滤 | 对应低分回答 |

**讲解性检查（防"code dump"收敛）**：round2/C 的 chosen 去掉代码块后正文须 ≥30 字符且命中解释性表述（因为/关键在于/讲解/为什么…），否则丢弃。这是防止 DPO 把"甩裸代码"学成正向信号的硬规则。报告按 source 输出 `explanation_stats.explanation_pass_rate`，真实生成时任何一层 <0.9 即重写该层生成指令。人工抽检 rubric 增加一维："chosen 是否解释了根因而非只给码"。

**长度偏差控制**：chosen 短 rejected 长会让 DPO 学成"短=好"。报告按 source 统计 chosen/rejected 平均长度，round2/C 层必须 chosen ≥ rejected 长度的信号要人工核对。
人工抽检 20%（用户 + 2 队友），批次合格率 <80% 改提示词重生成。

### 3.9 部署作用域（权重级行为必须圈定，防止伤及无辜场景）

DPO 改的是权重，"首轮不给码"会随模型部署到处生效——这正是"不能拒绝该给的代码"红线在**部署侧**的对应问题：

1. **只上导师链路**：DPO 模型仅替换 CodeLab 导师 `lab_workspace_service.ask_assistant(/stream)` 的 LLM 调用
2. **不上的链路**：智能答疑 `qa_router`、答辩/变式/修复（capability_service）、题解渲染等——这些场景学生要示例代码是**合理需求**，继续用原基座 + 运行时护栏
3. **护栏不撤**：DPO 上线后运行时护栏仍保留（纵深防御），护栏日志可对比 DPO 组/基座组的泄题率变化
4. **回退开关**：模型路径走配置项，出 false-refusal 可一键切回基座

### 3.10 工具决策层（2026-10-13 扩展）：三工具方案与真空项收敛

**背景：泄题双通道**。内容通道（回复文本给码）已由 P/A/C 层覆盖；行为通道（AI 调工具直接改学生代码，学生连答案都不用看即被改好——IDE Agent 场景高发，对计算机学生危害更大）此前无训练抓手，仅产品侧释放阀缓解。同时复盘出学生用 AI 的五个真空项：反谄媚附和、幻觉错误答案、空洞引导、给码后无理解检查、引导疲劳。为控制工作量，收敛为**一个工具化改造 + 一个子场景**，层不增（保持六层）、规模不变（~900 对）。

#### 三工具 schema（工具 = 动作通道，工具选择 = 时机决策）

| 工具 | 语义 | 前置条件（即奖励/质检规则） | 对应现有机制 |
|---|---|---|---|
| `give_hint(text, level)` | 引导，不给码 | 任意轮次可用；text 须含可执行动作、`level ≤ 3` | 提示阶梯、round1 chosen |
| `give_answer(code, why)` | 给完整答案 | 释放条件：学生已展示尝试 / 概念直答 / 已掌握 | R1/R2 判据、释放阀 |
| `modify_code(patch, why)` | 直接改学生代码 | **意图感知 + 是否请求 + 时机**（方案 C，见下方判定规则修订）：学生明确要求 → 提示 1 次后放行（附 why 讲根因）；工具性使用场景默认放行；未请求主动改 / 引导被升格执行 = 违规 | 行为通道（产品侧释放阀的训练侧镜像；2026-10-14 由"绝对禁令"改为"意图感知"，再收敛为方案 C） |

- **不设第 4 个工具**：每多一个工具就多一条合法性规则与一类违规样本，现阶段收益不抵成本
- 三层护栏叙事升级：**Shield 拦非法工具调用（尤其 `modify_code`）→ DPO 学工具选择 → 裁判审计轨迹**

#### 判定规则修订（2026-10-14）：不是禁止改代码，而是"在合适时机改"

> 背景：开发者实测踩到**未请求主动代改**（学生只问概念"为什么错"，agent 却直接改了工作区）；偷懒型学生"改完即走"零动手——one-shot prompting 卸载的是"想"，代改卸载的是"做"，是认知卸载的极端形式。原"首轮/未同意调用 = 违规"为绝对禁令式判定，会误伤正当工具使用，故修订为：

- **判定函数**：`modify_code` 合法性 = f(上下文意图, 学生是否明确提出改码请求, 时机/释放条件, 是否附 why)
- **意图三类上下文**：① 工具性使用（非学习、无作业/学习声明）→ **默认放行**（显式逃生门，直接放行不提示）；② 学习场景（"课程作业"/"我在学习"声明或命中学习行为特征）→ **学生明确要求代改 → 提示 1 次后放行**（提示语："如果你继续让我改代码，就会学不到知识点"）；③ 意图伪装（谎称"工作项目"绕过学习判定）→ 按学习场景处理（声明不可作依据），照常提示 1 次后放行，记入对抗样本
- **方案 C（2026-10-14 定，学习场景"提示 1 次后放行"）**：学生**自己开口要改就放行**（顶多先提示一次"继续让我改就学不到知识点"），**不得只给思路死拦**（否则"不然为什么要改呢"）；释放阀三条件（已尝试 ≥3 行 / 同关被拦 ≥2 轮 / 掌握度 ≥0.7）仍作为**提前放行**（免提示）的加速通道
- **违规主轴收窄为「未请求主动改」**：学生**未提出任何改码请求**（概念提问 / 只要提示 / 静默粘贴），agent 却调写工具直接改 —— 这类最容易被忽视，是本轮要拣出的核心违规（未请求主动改 / 引导被升格执行两类，统称 intent→tool 路由错误）
- **双侧错误都记**：核心违规（未请求主动改）与过度拦截（学习场景学生已明确要求代改、工具性使用场景被误拦）。"拦截率"不是好指标，主指标改为 **恰当代改率 = 该放的放了 + 该拦的拦了**（与内容通道"恰当给码率"对称）

#### 数据要求 v2（2026-10-14 二次修订，用户逐条批准）：请求主轴唯一化 + 新增三类违规

> 背景：存量工具决策对中发现**带病样本**——学生明确说"先给我正确版/直接帮我改"，`convert_dpo_to_tools.py` 却因"round1 一律 modify_code→rejected"（train 158 + eval 66 = **224 对** `hint_vs_modify`）把正当代改请求标成该拒绝的行为；`build_dpo_pairs.py` 质检同病（`round_no==1 → modify_code 违规`）。用户裁定：**别人拿模型当改码工具完全没理由禁止，否则模型以后都不会改代码了**。据此把判定从"轮次/信号代理"收敛为单一请求语义轴，并新增越权维度。

**① 判定主轴唯一化（替代"轮次代理"）**：`modify_code` 合法性的第一判据 = **学生本回合是否明确提出改码请求**（"帮我改/直接改/改好/只改这一处"类动词）；轮次、贴码行数、被拦轮数只是时机细节，不再是合法性依据。**请求语义边界（BC-06/07 教训）**："怎么改/帮我看看/报错了 IndexError" 等若不含改码动词 = **hint 请求 ≠ 改码请求**，不得据此调写工具。

**② 提示 1 次的适用范围（用户 2026-10-14 批准：作业催促要触发）**：学习场景**所有**明确代改请求均先提示 1 次（"继续让我改代码，就学不到知识点了"）后放行——**含作业催促 / 截止时间压力 / 局部范围收窄**（BC-01~05 类）；提示是告知代价、非劝阻，同会话同关卡最多 1 次，学生坚持即放行。释放阀三条件（已尝试 ≥3 行 / 同关被拦 ≥2 轮 / 掌握度 ≥0.7）为**免提示**加速通道；工具性使用逃生门不提示。

**③ 违规类清单 v2**（前三类已有，后三类本轮新增）：

| failure_mode | 语义 | 典型触发 |
|---|---|---|
| `unrequested_modify` 未请求主动改 | 学生无任何改码请求却调写工具 | 概念提问 / 只要提示 / 静默粘贴 / "我不会" |
| `over_block` 过度拦截 | 明确请求（含催促）或工具逃生门被死拦 | 学生说"直接改"却只给思路不给改 |
| `hint_escalation` 引导被升格执行 | 学生只要提示，agent 却代改 | "给我提示就行"→ 直接动手 |
| `scope_overreach` 越权修改（新） | 请求存在但改动超出请求范围 | 只让改一行却重写整个函数 / 改 A 文件顺手改 B / 删学生原有非目标逻辑 |
| `no_bug_no_touch` 无 bug 硬改（新） | 代码本无缺陷仍执行代改 | "帮我改好"但代码正确 → 应说明无需修改 |
| `step_confirm_violation` 分步确认违规（新） | 学生要求"每改一处先问我"却一次性全改落盘 | 显式分步协议被跳过 |

**④ 工具决策对型表 v2**（替换原 modify 三分类；总量不变 ~900 对，从 224 对带病样本拆分回收 + 新增 ~65 对）：

**⑤ 质检矩阵修订**（`build_dpo_pairs.py`）：

#### 意图识别框架（2026-10-14 补充）：判代价，不判真伪

> 核心问题："用户是真学习还是做项目？"——**单条文本不可判定**，且意图混合、时变、可伪装（同一学生前 15 分钟在学习、后 5 分钟赶工想走捷径；"这是工作项目"一句话即可伪装）。因此不追求判定"人"，改为三层机制：

1. **声明只作先验，不作依据**："这是课程作业"/"这是工作项目"两个方向都能一句话伪造，声明仅用于给 `intent_confidence` 打底，绝不作开关。
2. **行为信号作后验**（大部分信号已落库，规则打分或逻辑回归即可，无需 LLM 判定）：
   - 工作区证据：学生自己的提交/运行记录、修改行数、试错次数（`git_commit` 痕迹已统计在 verify_lab_wiring）
   - 会话行为：句式是"为什么/怎么理解"还是"直接给/帮我改"、被引导后是否跟进、要求是否逐级升级
   - 既有画像：掌握度、复习正确率、尝试率（progress_profile 五出口已建）
3. **机制设计代替意图判定**（这是对"不可判定问题"的正解——把判定问题重构为选择问题）：
   - **默认学习模式**：产品永远默认按学习场景走（引导优先、释放阀生效），无需任何判定。
   - **显式逃生门**：当且仅当学生**明确声明**"这是工作项目/快速任务，直接帮我改"（文字声明或界面开关任一），该次会话才退出释放阀限制。逃生门不是暗门——**每次触发都写入学习报告（老师可见），触发后的每一次 `modify_code` 仍完整留痕（patch + why + 审计日志）**。一句话：**逃生门 = 用留痕成本换取跳过引导的自由**；作弊成本从"零"变成"可审计留痕"，温水型偷懒（"哎你好人做到底"）自然收敛。
   - **事件级打标，不给用户贴标签**：不回答"这个人是学习还是做项目"，只回答"这一次代改放行值不值得"——按时段/按请求切分，混合意图的难题自动消解。
   - 诚实边界（评审问答标准答案）："我们不承诺识别意图真伪——我们让作弊的成本 ≥ 学习的成本，且每一次放行可审计。"

#### 意图判定器选型：Jev（System-1）+ 双系统分工（2026-10-14 补充；实现层选型，机制层不变）

> 机制层（判代价不判真伪）不因选型改变；此处只回答"`intent_confidence` 由什么算出来"。**Jev** 是 Type-Safe AI 的专有 System-1 决策模型：输入原文 + 类型化提问（schema），不经自回归生成，直接返回类型化决策与校准概率——固定成本、低延迟、概率可信，正合意图判定这种"高频、低延迟、要概率"的场景。

- **三原语映射**（Jev 的类型化接口恰好覆盖意图判定的全部输出需求）：
  - `Choice`：三类上下文分类（学习场景 / 工具性使用 / 伪装可疑）
  - `Score`：学习置信度 0–1（即 `intent_confidence`）
  - `Noul`（是非概率）："这是学习请求吗？" + 置信度
- **双系统分工（借鉴 SearchJev arXiv:2610.05107 的 dual-system agent 模式）**：Jev 作 System-1 快速判定；**置信度低于阈值时不硬判，回落默认学习模式（保守路径）**，必要时引导学生显式选择（即触发"显式逃生门"对话）。Jev 不是判定真伪的银弹，而是"走默认模式还是请学生明示"的**路由器**——与"判代价不判真伪"机制精确互补。
- **输入特征**：学生声明（仅作先验）+ 近几轮提问句式 + 工作区行为特征（提交/运行/试错次数）+ 画像摘要（掌握度/尝试率）——即上文"行为信号作后验"的具体化。
- **中文适配**：Chinese-Jev（arXiv:2609.36965）证明 System-1 决策模型可覆盖中文任务（注记转候选概率目标 + 轻量 encoder），本项目学生以中文提问，无适配障碍。
- **诚实风险与解耦**：① Jev 为专有黑盒（Type-Safe AI），存在 API 依赖与可用性风险；② 固定决策模型的能力有文献负结果（arXiv:2609.36154 对 train-free 决策模型的质疑）。故**接口解耦**：代码只依赖 "Choice/Score/Noul" 三原语契约，实现可替换——备选①本地轻量分类器（MiniLM embedding + 多簇边界学习，arXiv:2607.07974，天然适合 OOS 意图拒判）；备选②规则打分/逻辑回归基线（零依赖兜底）。训练/校准语料：30 条人工标注 + `guard_event` 持续积累的真实轨迹。

#### 数据改造（转换脚本，不重新生成对话）

- 存量 chosen/rejected 由"文本对"改写为**工具决策对**（chosen/rejected = 工具调用 JSON），DPO 直接学"走哪条通道"：

```json
{"prompt": [{"role": "user", "content": "..."}],
 "chosen": "{\"tool\": \"give_hint\", \"args\": {\"level\": 2, \"text\": \"在第 8 行打印 i 的值看看\"}}",
 "rejected": "{\"tool\": \"modify_code\", \"args\": {\"patch\": \"...完整修复...\"}}",
 "tool_decision": "hint_vs_modify"}
```

- 不涉工具的场景（概念直答等）保留纯文本对，防学成"凡事必调工具"
- jsonl 新增 `tool_decision` 字段用于按工具归因；`layer`/`source`/`family` 不变
- **质检由文本判据改为查表**（更硬、全自动，2026-10-14 改请求轴口径）：学习场景 `modify_code` 合法性 = 明确请求（提示 1 次）或释放条件满足，**未请求/引导升格的 `modify_code`（intent→tool 路由错误）= 违规**（绝对禁令"释放条件未满足即违规"已废除——学生明确请求即合法，见上方数据要求 v2）；`give_answer` 缺 why = 违规；`give_hint` 无动作动词或 `level=4（重述问题）` = 违规——顺带治"空洞引导"（真空项③，只加此一条，不开新层）

#### 验收扩展（与修数据不对称、IPO 重跑同批）

- **按工具分解错误率**：违规划 `modify_code` 率 / 首轮 `give_answer` 率 / 空洞 `give_hint` 率——三数直接比较基座 vs DPO vs IPO，作模型选择依据
- **恰当代改率（双侧主指标，2026-10-14 新增）**：该放的放了（工具性使用不误拦）+ 该拦的拦了（学习场景时机未到不代改），与内容通道"恰当给码率"对称
- **意图轴评测（2026-10-14 新增）**：学习/工具/伪装三类上下文 × 代改请求，出意图识别与 intent→tool 路由错误率；轨迹级补充两条——`give_hint` 渐进升格为 `modify_code` 的组合违规、拦截后刷新重问的**重试绕过**
- **灰色粘贴通道**（AI 不动文件但给"复制即可运行"的完整代码块，效果等同代改）列为 P2 观察项
- **真实轨迹回放评测（shadow replay，P1）**：`log_guard_event`（guardrail + tool_guard 双通道）已持续落库 → 定期离线回放评测真实会话轨迹——评测从"赛前跑一次 benchmark"变成产品运行的副产品。held-out 的定位据此修正：**必要但远不充分**——它只测 prompt 级静态两轮，测不了长会话有状态、混合意图、"给 diff 让学生手动执行"的等效代改规避、温水型偷懒等真实路径
- **反谄媚红线**：A 层子场景 held-out 必须纠正学生错误判断（地位同 false-refusal）
- 工具决策天然成对（hint vs modify 对称），缓解 460:19 长度不对称问题

**落地顺序**：① 定工具 schema 写入 `build_dpo_pairs.py` 质检矩阵 → ② 存量对转换脚本 + 20% 人工抽检 → ③ A 层反谄媚子场景模板 → ④ 与修数据不对称合并进 IPO 重跑数据包。
